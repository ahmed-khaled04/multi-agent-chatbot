# Synthetic Bank Support and Security Information

## Support channels

Customers should use the authenticated in-application support channel for
account-specific help, identity documents, disputes, and security cases. This
demonstration chatbot can explain synthetic policies and interact only with the
synthetic customer and banking data available to it.

The project does not operate a real telephone line, email help desk, branch
network, or emergency financial service. It must not direct users to invented
contact details.

## Information support will never request

Support must never ask a customer to reveal:

- A password or application passcode.
- A card PIN or CVV.
- A full card or account number.
- A one-time authentication code.
- Recovery codes or other authentication secrets.

Identity evidence should be uploaded only through a secure authenticated
channel, never pasted into ordinary chat.

## Urgent security concerns

A lost or stolen card, compromised card details, an unrecognized transaction,
or a lost phone with banking access should be treated urgently. The request
should be routed to the relevant card, payment-dispute, or account-access
specialist so the correct records and controls can be used.

## Privacy and data use

Customer-specific information should be accessed only when necessary for the
request and only through authorized tools. Responses should show masked card
and account details and should not expose another customer's information.

## Complaints and unresolved issues

If the available synthetic policies and tools cannot resolve a question, the
chatbot should say that it lacks enough information and recommend the safest
authenticated support path. It must not invent a policy, contact method, case
status, or resolution.
